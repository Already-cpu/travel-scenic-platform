# 前端答辩速记：行旅志旅游景点网站

这份材料按当前代码整理，适合小组作业答辩前快速熟悉。答辩时重点讲清楚“页面结构、数据流、权限分离、组件化和功能闭环”，不需要逐行背代码。

## 一句话介绍项目

本项目是一个基于 Vue 3 的旅游景点网站前端，用户端负责景点浏览、搜索、下单、评价、收藏和个人资料管理；管理员端负责景点、订单、用户、评价和统计数据管理。前端通过 Axios 调用 Spring Boot REST 接口，使用 Vue Router 管理页面，使用 Element Plus 完成交互组件，使用 ECharts 展示后台统计图表。

## 先记住这条数据流

```text
用户操作页面
  → Vue 组件中的事件函数
  → frontend/src/api/http.js 封装的接口
  → Spring Boot 后端接口
  → MySQL 数据库
  → 后端返回 JSON
  → Vue 响应式变量更新
  → 页面自动重新渲染
```

例如“预订门票”的流程是：用户在景点详情页填写日期、票种、数量和联系人，前端校验表单后调用 `orderApi.create()`，后端创建订单并返回结果，前端提示成功并跳转到个人中心。

## 重点文件怎么讲

### 1. `main.js`：前端启动入口

可以这样说：

> `main.js` 使用 `createApp(App)` 创建 Vue 应用，然后注册 Vue Router、Element Plus 和图标组件，最后挂载到 `index.html` 中的 `#app` 节点。这样整个项目就从根组件开始运行。

需要理解的三个词：

- `createApp`：创建 Vue 应用。
- `app.use`：安装路由或 UI 组件库插件。
- `mount('#app')`：把应用放入页面节点。

### 2. `router/index.js`：页面切换和登录拦截

项目有两套路由：

- 用户端：`/`、`/scenic`、`/scenic/:id`、`/account`。
- 管理端：`/admin/login`、`/admin/dashboard`、`/admin/scenic`、`/admin/order`、`/admin/user`、`/admin/comment`。

`/admin` 路由使用 `adminAuth`，`/account` 使用 `userAuth`。进入页面前，路由守卫检查 `sessionStorage` 中是否有对应 Token，没有就跳转登录页。

答辩时一定强调：

> 前端路由拦截主要是改善用户体验，真正的权限校验仍然由后端 Spring Security 和 JWT 完成。用户 Token 和管理员 Token 分开保存、分开校验，两个账号体系不互通。

### 3. `api/http.js`：统一请求层

项目没有在每个页面里重复写 Axios 配置，而是集中创建了一个 `http` 实例。

请求拦截器会根据当前路径判断是用户端还是管理员端，然后从 `sessionStorage` 取出 `user_token` 或 `admin_token`，放入请求头：

```text
Authorization: Bearer <Token>
```

响应拦截器统一判断后端返回的 `code`。`code === 200` 时直接返回 `data`；如果是错误，就弹出 Element Plus 消息提示，遇到 401 时清除对应 Token。

接口又按业务分组，例如：

- `scenicApi`：景点列表、详情、增删改查。
- `userApi`：注册、登录、个人资料。
- `orderApi`：创建、查询、支付、取消订单。
- `commentApi`：查看和发表评价。
- `favoriteApi`：收藏和取消收藏。
- `adminApi`：后台管理和数据统计。

### 4. 首页和景点详情页

首页 `Home.vue` 在 `onMounted` 生命周期中请求热门景点和筛选统计，数据显示到轮播图和景点卡片中。轮播图不是写死在页面里的，而是由后端返回景点数据后循环渲染。

详情页 `ScenicDetail.vue` 负责三类交互：

1. 展示景点信息和评价列表。
2. 调用订单接口完成预订。
3. 调用收藏和评价接口完成用户互动。

在页面上，用户没有登录时会跳转登录；没有合适订单时不能评价。但最终是否能评价，仍由后端再次判断，避免只依靠浏览器校验。

### 5. 管理员仪表盘 `Dashboard.vue`

仪表盘首屏按照需求说明书保留五个并行请求：总览、景点浏览量、订单趋势、地区分布、最近订单。

页面上有：

- 四张统计卡片：用户、景点、订单、评价。
- 四个快捷操作入口。
- 浏览量 TOP10 水平柱状图。
- 近 12 个月订单面积折线图。
- 景点地区环形图。
- 最近 5 条订单。

下面的扩展分析还包括：景点浏览/预订/收藏热度、指定景点 1—5 星评分分布、订单日/月/年数量和金额、用户注册和活跃统计。

`AnalyticsChart.vue` 是可复用的 ECharts 容器，负责初始化图表、监听容器尺寸变化，并在组件销毁时调用 `dispose()`，防止重复初始化和内存泄漏。

## 最容易被问到的 10 个问题

### 1. 为什么使用 Vue 3？

Vue 3 适合构建单页应用，组件化程度高，响应式数据更新直观，配合 Element Plus 可以快速完成表单、表格、弹窗和分页等页面。

### 2. 什么是组件化？项目哪里体现了组件化？

把页面拆成职责清晰、可以复用的部分。例如 `ScenicCard.vue` 负责景点卡片，`AnalyticsChart.vue` 负责图表初始化和销毁；用户布局和管理员布局也分别抽成独立组件。这样可以减少重复代码，后期修改更容易。

### 3. `ref` 和 `reactive` 是做什么的？

它们都是 Vue 3 的响应式工具。`ref` 常用于基本值或单个状态，例如加载状态、列表和当前页；`reactive` 常用于表单对象，例如搜索条件、登录表单和订单表单。值发生变化时，模板会自动更新。

### 4. 前端如何实现用户和管理员分离？

页面路由、登录入口、Token 名称和后端身份类型都分开。用户端使用 `user_token`，管理员端使用 `admin_token`；前端请求时根据 URL 选择对应 Token，后端再根据 JWT 类型限制接口权限。管理员没有用户注册入口。

### 5. 前端如何保证安全？

前端只做页面级拦截和输入校验，不能代替后端安全。真正的身份认证、管理员权限、订单归属、评价资格和上传文件检查由后端完成。密码不在前端保存，登录后只保存后端返回的 Token。

### 6. 为什么使用 Axios？

Axios 支持 Promise，适合调用 REST 接口。项目通过请求拦截器自动添加 Token，通过响应拦截器统一处理成功、失败和 401 状态，避免每个页面重复写相同逻辑。

### 7. ECharts 在项目中做了什么？

管理员仪表盘用 ECharts 把后端统计数据转成柱状图、折线图、环形图和评分分布图。图表数据来自 MySQL 汇总，不是前端随机生成；日/月/年切换时会重新请求对应统计接口。

### 8. 页面刷新后为什么还知道登录状态？

登录成功后 Token 保存在 `sessionStorage`。刷新页面时路由守卫读取 Token，布局组件再调用个人信息接口恢复用户资料。关闭浏览器标签页后 `sessionStorage` 会清除，适合课程演示场景。

### 9. 页面如何适配手机？

通过 CSS 媒体查询，在较窄屏幕下把多列布局改成单列或两列，调整导航、表格和轮播图尺寸，并通过浏览器测试确认 390px 宽度没有横向溢出。

### 10. 前端和后端是如何配合的？

前端负责界面、交互、参数收集和结果展示；后端负责业务规则、身份认证、权限校验和数据库操作。例如前端提交评价后，后端会检查用户是否有已经游览的有效订单，不能只相信前端按钮是否显示。

## 建议的现场演示顺序

1. 打开用户首页，展示实景背景、轮播图和热门景点。
2. 进入景点列表，演示关键词、地区、类型筛选和分页。
3. 打开一个景点详情，展示图片、价格、评价、收藏和预订入口。
4. 使用用户账号登录，进入个人中心，展示订单、头像上传和评价。
5. 退出用户端，打开 `/admin/login`，使用管理员账号登录。
6. 展示仪表盘四张卡片、三张核心图表和最近订单。
7. 向下滚动展示评分、订单日/月/年切换、用户活跃统计。
8. 最后进入景点管理或评价管理，展示管理员功能。

## 现场不要说错的地方

- 不要说订单是真实售票，项目中的支付是模拟支付。
- 不要说评价都是真实游客评价，带“演示评价”的内容是课程演示数据。
- 不要说前端单独保证安全，应说前后端共同完成，后端是最终校验方。
- 不要说 H2，项目使用的是独立 MySQL 数据库。
- 不要说用户和管理员共用账号，两个账号体系是分开的。

## 30 秒自我介绍示例

> 我主要负责本项目的 Vue 前端实现。前端采用 Vue 3、Vue Router、Axios、Element Plus 和 ECharts，分为用户端和管理员端两套界面。用户端实现了景点浏览、搜索筛选、详情、预订、评价、收藏和个人中心；管理员端实现了景点、订单、用户、评价管理和数据统计。项目通过 Axios 与 Spring Boot REST 接口通信，使用路由守卫做页面级登录拦截，后端通过 JWT 做最终权限校验。为了便于维护，我把公共布局、景点卡片和图表容器抽成了组件，并做了移动端适配。
