# 行旅志旅游景点网站

Spring Boot + Vue 3 前后端分离旅游网站，使用独立 MySQL 数据库，不含 H2。
用户端与管理端使用独立页面布局、登录入口、账号表和 JWT 身份；用户 Token 不能访问管理员接口，管理员 Token 也不能操作用户中心。

## 本机浏览

- 用户端：http://localhost:5173/
- 管理端：http://localhost:5173/admin/login
- 管理员：`admin / admin123`
- 演示用户：`13800138000 / 123456`
- 新增演示用户：`19900001001` 至 `19900001060`，密码 `123456`。

这些是开发环境演示账号。已有账号再次导入时不会重设密码。正式部署必须修改默认凭据、JWT 密钥和数据库密码。

## 一键运行与交付包

Windows 下可直接双击根目录的 `一键启动.bat`。脚本会检查 Java/MySQL、自动导入独立 MySQL 数据库、启动已经内嵌 Vue 页面的 Spring Boot JAR，并打开 `http://localhost:8080/`。关闭时双击 `停止项目.bat`。

一键运行版不需要 Node.js，也不需要分别启动前端和后端；仍需预先安装 Java 8+ 和 MySQL 8+。默认尝试数据库账号 `root/root`，连接失败时会安全提示输入本机 MySQL 账号密码。详细说明见 `运行说明.txt`。

## 数据与照片

全新导入提供 24 个真实景点、61 个演示用户、516 条演示订单、240 条演示评价、288 条收藏；每个景点 10 条带“演示评价”标记的样例。评价关联已完成的对应订单，生成时间不早于游览时间，订单时间不早于用户注册时间。
演示订单覆盖近 12 个自然月，空时间段仍显示为零。

本机保留原有数据后的验收快照是：24 个景点、74 个用户、547 条订单、265 条评价、306 条收藏。此数目会随实际操作变化，不应与空库演示数量混淆。

首页使用桂林漓江实景背景与热门六景点轮播。24 张照片存放在 `frontend/public/scenic-images`，运行时不依赖远程图床。新增照片的来源和许可见网站页脚“实景照片来源”；原有 1–10 号照片的对外传播授权尚需另行复核。图片无法加载时使用中性占位图，不用另一个景点冒充。

所有价格、开放时间、示例评价、浏览量和订单仅供课程演示，支付为模拟支付，不提供真实票务交易。实际旅行请以景区官方信息为准。

## 1. MySQL

使用 MySQL 8.0 或更高版本，通过 Navicat/MySQL 客户端执行：

- 全新安装：`database/travel_website.sql`（一个完整独立 SQL 文件）。
- 已有项目升级：先备份，再依次执行 `database/migrations/20260927_catalog_correction.sql`、`database/migrations/20261007_feature_upgrade.sql`、`database/migrations/20261008_feature_upgrade6.sql`、`database/migrations/20261008_profile_wallet.sql`，最后按需执行 `database/seed_demo.sql`。
- 仅创建空表：`database/schema.sql`。

脚本不含 DROP/TRUNCATE/DELETE，不清空表，不覆盖用户、密码、头像或订单。增量数据使用稳定演示订单号及唯一键防止重复。
不要导入 `work/backups`，它是本机私有恢复备份，不属于交付数据。

默认数据库：`localhost:3306/travel_website`，账号/密码：`root/root`。在 `backend/src/main/resources/application.yml` 修改，或用 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD` 覆盖。

## 2. 启动后端

需要 Java 8+ 和 Maven。请在 backend 目录启动，以保证本机上传文件路径一致。

```powershell
cd backend
mvn package
java -Duser.timezone=Asia/Shanghai -jar target/travel-website-backend-1.0.0.jar
```

接口地址：http://localhost:8080。Windows 更新运行中的 JAR 前应先停止该项目后端，避免文件锁导致打包失败。

## 3. 启动前端

需要 Node.js 18+。

```powershell
cd frontend
npm ci
npm run dev
```

访问 http://localhost:5173。开发服务器将 `/api`、`/uploads` 代理到 8080。
`npm run build` 生成 dist；生产部署时必须同样配置接口/上传文件代理和 SPA 路由回退。

技术栈：Vue 3、Axios、Element Plus、ECharts、Spring Boot 2.7、MyBatis-Plus、Spring Security、JWT、MySQL。
构建工具沿用本项目的 Vite（需求文档的开发环境列出的是 Vue CLI）；本次未迁移构建工具。

## 功能

用户端：手机号注册、密码/短信验证码/扫码登录与一键演示登录、热门推荐与轮播、热门城市/季节推荐/站内榜单/编辑精选攻略/旅行主题精选/出发前准备清单/旅行服务/旅行灵感入口、动态地区/类型筛选、卡片或纵向列表视图、搜索及价格排序、AI 旅行助手、详细景点攻略、景点详情左侧纵向目录、分票种价格与库存、日期/数量选择、下单后立即支付/取消、图文评价、收藏与个人资料。个人资料包含旅客姓名、手机号、昵称和头像，预订门票时会自动带入姓名与手机号。我的行程包含下一站提示、订单/待支付/收藏/评价概览、订单状态筛选和独立的“我的钱包”；钱包余额保存于 MySQL，余额支付会真实校验和扣减，扫码支付不扣钱包。景点详情包含真实评价均分与评分分布、景点亮点、动态推荐游览路线、票务规则、服务设施、按景点类型变化的交通/拍照/餐饮/安全实用攻略、常见问题、行前参考和同类型推荐。未登录点击预订、收藏、评价或“我的行程”时，会先显示可关闭的登录提示弹窗；用户确认后才进入登录页，登录页本身也可关闭。
登录用户无需购票或等待游览日期即可评价景点；每名用户对同一景点仅可评价一次，每条评价最多上传 6 张图片。个人中心可上传头像，预览后点击“保存信息”生效，顶部头像同步更新。

管理端：独立登录与一键演示登录、景点分页与增删改查/上下架/图片上传、联动省市、开放开始/结束时间选择及先后校验、多票种价格与库存维护、订单状态/日期/用户关键词筛选与详情、支付方式查看、用户启用/禁用/删除、评价图片查看、隐藏/删除和连续多次回复。后台首页增加“今日运营工作台”，集中展示待支付订单、游客评价和景点内容维护入口。

AI 助手通过 `POST /api/assistant/chat` 提供站内景点推荐、预算/地区/偏好筛选及购票和评价指引。它是项目内置规则型助手，不依赖收费外部模型，断网环境也可用于课程答辩。

短信和扫码登录是课程演示流程：短信验证码固定为 `123456`，扫码页提供“模拟扫码成功”按钮。两者都由后端签发真实用户 JWT，但不接入真实短信运营商或第三方 App；管理员仍只能通过独立管理端账号登录。

登录表单只在用户点击“登录”“验证码登录”或“进入管理后台”按钮时执行校验；输入、失焦和按回车不会提前显示错误。校验提示出现后，用户开始填写对应字段时会立即清除该字段的红色提示。

上传支持 JPG/PNG/GIF/WebP，单张不超过 10MB；检查文件签名，不接受 SVG/HTML。文件保存在 `backend/uploads`，仅上传需要登录，显示图片无需 Token。

## 数据可视化（需求 4.2.6、4.3）

仪表盘首屏通过五个并行接口获取数据：

1. 四张卡片：用户、景点、订单、评价总量。
2. 四个快捷入口：新增景点、订单、用户、评价。
3. 浏览量 TOP 10 水平柱状图、近 12 月订单面积折线图、各省景点环形图。
4. 右下角最近五条订单。
5. 扩展区：所有景点浏览/有效预订/收藏排名、单个景点 1–5 星分布、日/月/年订单数量与金额、注册趋势及活跃人数，支持全屏大屏。

统计口径详见 `database/README.md`。所有图表读取 MySQL 汇总，无随机前端模拟数据；空值与缺失时间段补零，图表在页面离开时销毁，尺寸变化自动适配。
