# 独立 MySQL 数据文件

## 导入方式

`travel_website.sql` 是可单独在 Navicat/MySQL 中执行的完整文件，包含建库、独立账号、票种库存、图文评价、多次回复、24 个景点及演示数据，无 H2、无内存数据库。

| 文件 | 用途 |
| --- | --- |
| travel_website.sql | 全新安装的结构与公开演示数据，重复导入不重置现有数据 |
| schema.sql | 仅创建数据库、业务表 |
| seed_demo.sql | 向已有兼容结构追加演示数据，幂等执行 |
| migrations/20260927_catalog_correction.sql | 仅修正旧版已知的九条错配景点记录，保留 ID 与关联数据 |
| migrations/20261007_feature_upgrade.sql | 已有数据库升级多票种库存、评价图片和多次回复；只执行一次 |
| migrations/20261008_feature_upgrade6.sql | 已有数据库新增订单支付方式字段，非破坏性且可重复执行 |
| migrations/20261008_profile_wallet.sql | 已有数据库新增旅客姓名和钱包余额，并用昵称补全历史用户姓名 |
| base-scenic.json / scenic-catalog.json | 24 个景点的公开目录；后者包含新增照片来源 |
| generate-demo.cjs | 生成 seed_demo.sql 与完整 SQL，不读取现有数据库 |

已有数据库请先备份，依次执行迁移后再执行增量种子。`20261007_feature_upgrade.sql` 含新增字段，只执行一次；两份 `20261008` 迁移可安全重复执行。不要删除表或导入本机私有备份来获得演示数据。为保留历史记录，旧订单保留购票时的景点名称、票种与金额快照。

全新导入：24 景点、61 用户（含默认体验账号）、516 订单、240 评价、288 收藏。60 个新增演示用户以“演示·”命名，订单号以 DEMO_V2_ 开头，评价内容以“【演示评价】”开头。每条演示评价均对应已完成的订单；每个景点的十名评价者不重复。账号按手机号查重，订单按唯一订单号查重，评价和收藏按用户+景点查重。

演示数据时间以首次导入当天为锚点。重复导入不会改写原有时间或不断增加新的样例。已有账号、头像、昵称、密码、订单和评价不被覆盖。

## 统计口径

- 总用户/景点/订单/评价：相应表总记录数，含禁用、下架、取消和隐藏状态。
- 浏览排行：累计 views 前十，按浏览量降序，同数按 ID 排序。
- 有效预订：当前状态为 PAID/COMPLETED 的订单数，不是购票人数。
- 收藏：当前收藏记录数量。
- 订单时间：按 create_time 归组；范围起止日期均包含在统计中，SQL 采用起始闭区间与次日零点开区间。
- 下单金额：范围内全部订单 total_price 之和，包含取消/未支付。
- 有效已付金额：同一创建时间范围内当前 PAID/COMPLETED 订单的金额之和，不等同支付日流水。
- 默认日/月/年：近 30 天、近 12 个自然月、近 5 个自然年；缺失区间补零。日统计最多 367 天，月/年统计最多 3661 天。
- 用户注册：近 12 月新增用户；今日/近 30 天活跃为 enabled 用户的 last_login_time，按用户去重。近 30 天是滚动 30 天，非月度页面访问次数。
- 评分：逐个景点公开评价（status=1）的 1–5 星数量与均分，隐藏评价不计入；零评价均分显示“—”。
- 地区：所有景点按省级地区分组，含下架景点。
- 运行环境使用 Asia/Shanghai，请保持 JVM、MySQL 与业务日期时区一致。

演示数据仅用于功能验证，不能作为真实用户增长、游客反馈、交易流水或官方票价对外发布。

## 账号与安全

默认 `admin/admin123` 只进入管理员端；`13800138000/123456` 进入用户端。
用户与管理员分别存储在 user、admin 表；密码使用 BCrypt；JWT 区分 USER/ADMIN。
生产环境必须自行更换默认密码和 JWT 密钥，并使用独立的 MySQL 最小权限账号。
